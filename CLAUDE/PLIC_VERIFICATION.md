# RV_PLIC Interrupt Controller Verification

This document describes the verification approach for the RV_PLIC (RISC-V Platform-Level Interrupt Controller) in OpenTitan.

## Overview

**Design:** RV_PLIC is OpenTitan's interrupt controller, implementing the RISC-V PLIC specification.

**Verification Strategy:** **FPV-only** (Formal Property Verification). No dynamic simulation testbench exists for RV_PLIC.

**Rationale for FPV-only approach:**
- Interrupt routing logic is well-suited to formal verification
- Exhaustive verification of all interrupt priority combinations infeasible via simulation
- Formal tools can mathematically prove correctness across entire state space
- Less complex than a full UVM testbench for this relatively straightforward IP

## Design Features

RV_PLIC manages interrupt sources from peripherals and routes them to processor targets (HARTs). Key features:

- **Configurable sources:** Up to 1023 interrupt sources (Earl Grey: 186 sources)
- **Configurable targets:** Multiple interrupt targets (Earl Grey: 1 target)
- **Priority-based arbitration:** Each source has configurable priority (0-7)
- **Per-target thresholds:** Targets only notified if interrupt priority > threshold
- **Interrupt enables:** Per-target enable/disable for each source
- **Edge or level triggering:** Configurable per-source via `LevelEdgeTrig` parameter
- **Claim/Complete protocol:** Prevents interrupt re-assertion until completion

## Design Structure

### Auto-Generated IP

RV_PLIC is **auto-generated** for each top-level design:
- Template: `hw/ip_templates/rv_plic/`
- Earl Grey instance: `hw/top_earlgrey/ip_autogen/rv_plic/`
- Darjeeling instance: `hw/top_darjeeling/ip_autogen/rv_plic/`

Parameters configured via top-level Hjson (e.g., `hw/top_earlgrey/data/top_earlgrey.hjson`).

### RTL Components

Located in `hw/top_earlgrey/ip_autogen/rv_plic/rtl/`:

1. **`rv_plic.sv`** (15KB) - Top-level module
   - Instantiates gateways, targets, and register block
   - Wires interrupt signals between components

2. **`rv_plic_gateway.sv`** (2KB) - Interrupt gateway (one per source)
   - Detects edge/level-triggered interrupts
   - Sets interrupt pending (`ip`) bit
   - Clears `ip` on claim
   - Prevents re-assertion until completion

3. **`rv_plic_target.sv`** (2KB) - Target logic (one per HART)
   - Arbitrates among enabled, pending interrupts
   - Selects highest priority (lowest ID for ties)
   - Generates `irq_o` if priority > threshold
   - Outputs `irq_id_o` for claimed interrupt

4. **`rv_plic_reg_top.sv`** (424KB) - Auto-generated register block
   - CSRs for priority, interrupt enable, threshold, claim/complete
   - Generated by `reggen` from `data/rv_plic.hjson`

5. **`rv_plic_reg_pkg.sv`** (29KB) - Auto-generated register package

### Register Map (Key CSRs)

Defined in `hw/top_earlgrey/ip_autogen/rv_plic/data/rv_plic.hjson`:

- **`PRIO[0..185]`** - Priority for each interrupt source (3 bits each)
- **`IP[0..5]`** - Interrupt pending bits (read-only, 186 sources / 32 bits per reg)
- **`LE[0..5]`** - Level/Edge configuration (0=level, 1=edge, one bit per source)
- **`IE0[0..5]`** - Interrupt enable for target 0 (186 bits across 6 registers)
- **`THRESHOLD0`** - Priority threshold for target 0
- **`CC0`** - Claim/Complete register for target 0 (read to claim, write to complete)
- **`MSIP0`** - Machine-mode software interrupt pending

### Assertion Module: `rv_plic_assert_fpv.sv`

**Key technique: Symbolic variables**

Uses symbolic variables to reduce assertion complexity:
- `src_sel` - Represents any interrupt source index
- `tgt_sel` - Represents any target index

Symbolic variables are constrained to valid ranges and held stable throughout verification, allowing a single assertion to cover all sources/targets.

**Assumptions (constrains formal environment):**
```systemverilog
`ASSUME_FPV(IsrcRange_M, src_sel > 0 && src_sel < NumSrc, clk_i, !rst_ni)
`ASSUME_FPV(ItgtRange_M, tgt_sel >= 0 && tgt_sel < NumTarget, clk_i, !rst_ni)
`ASSUME_FPV(IsrcStable_M, ##1 $stable(src_sel), clk_i, !rst_ni)
`ASSUME_FPV(ItgtStable_M, ##1 $stable(tgt_sel), clk_i, !rst_ni)
```

**Key Assertions:**

1. **`LevelTriggeredIp_A`** - Level-triggered interrupt pending
   ```systemverilog
   `ASSERT(LevelTriggeredIp_A, ##3 $rose(ip[src_sel]) |-> $past(intr_src_i[src_sel], 3))
   ```
   If `ip` rises, source must have been asserted 3 cycles ago.

2. **`LevelTriggeredIpWithClaim_A`** - IP assertion without claim
   ```systemverilog
   `ASSERT(LevelTriggeredIpWithClaim_A, ##2 $past(intr_src_i[src_sel], 2) &&
           !claimed |=> ip[src_sel])
   ```
   If source asserted and not claimed, `ip` asserts next cycle.

3. **`IpStableAfterTriggered_A`** - IP stability
   ```systemverilog
   `ASSERT(IpStableAfterTriggered_A, ip[src_sel] && !claimed |=> ip[src_sel])
   ```
   Once set, `ip` stays high until claimed.

4. **`IpClearAfterClaim_A`** - IP clearing
   ```systemverilog
   `ASSERT(IpClearAfterClaim_A, ip[src_sel] && claim[src_sel] |=> !ip[src_sel])
   ```
   Claiming clears `ip` immediately.

5. **`TriggerIrqForwardCheck_A`** - Forward IRQ assertion
   ```systemverilog
   `ASSERT(TriggerIrqForwardCheck_A, ip[src_sel] && prio[src_sel] > threshold[tgt_sel] &&
           max_priority && ie[tgt_sel][src_sel] |=> irq_o[tgt_sel])
   ```
   If enabled, pending, above threshold, and highest priority → IRQ asserts.

6. **`TriggerIrqBackwardCheck_A`** - Backward IRQ check
   ```systemverilog
   `ASSERT(TriggerIrqBackwardCheck_A, $rose(irq_o[tgt_sel]) |->
           $past(irq) && (irq_id_o[tgt_sel] == $past(i_high_prio)))
   ```
   If IRQ rose, prior cycle must have had correct conditions and ID.

7. **`IdChangeWithIrq_A`** - IRQ ID changes
   Ensures `irq_id_o` only changes when appropriate conditions met.

8. **`DataIntg_A`, `RspIntg_A`** - Bus integrity checks
   Validates TileLink data and response integrity encoding.

9. **`FatalAlertNeverdrops_A`** - Fatal alert persistence
   ```systemverilog
   `ASSERT(FatalAlertNeverdrops_A, ##1 !$fell(fatal_alert_i))
   ```
   Fatal alerts never drop (only reset clears).

### Bind File: `rv_plic_bind_fpv.sv`

Binds three assertion modules to DUT:

1. **`rv_plic_assert_fpv`** - Main PLIC assertions (above)
2. **`tlul_assert`** - TileLink protocol checker (from `hw/ip/tlul/`)
3. **`rv_plic_csr_assert_fpv`** - CSR access verification

### Coverage TCL: `coverage.tcl`

Defines coverage waivers for formal verification:
- Untied ports in integrity checkers
- Dead nodes in priority tree (for non-power-of-2 source counts)
- Level-triggered interrupt paths (edge-triggered not used in Earl Grey)
- Unconnected outputs in `prim_subreg` instances
- Alert sender coverage (verified separately)

## Testplan

Testplan in `hw/top_earlgrey/ip_autogen/rv_plic/data/rv_plic_fpv_testplan.hjson`.

Imports common CSR testplan and defines PLIC-specific testpoints:

| Testpoint                        | Description                                                             | Stage |
|----------------------------------|-------------------------------------------------------------------------|-------|
| `LevelTriggeredIp_A`             | If IP triggered, source should have been asserted (level-triggered)     | V2    |
| `LevelTriggeredIpWithClaim_A`    | Source assertion causes IP to set (if not claimed)                      | V2    |
| `IpStableAfterTriggered_A`       | IP stays set until claimed                                              | V2    |
| `IpClearAfterClaim_A`            | IP clears when claimed                                                  | V2    |
| `IpStableAfterClaimed_A`         | IP stays clear until completed and re-triggered                         | V2    |
| `TriggerIrqForwardCheck_A`       | IRQ triggers when conditions met (enabled, pending, priority, threshold)| V2    |
| `TriggerIrqBackwardCheck_A`      | If IRQ set, prior conditions must have been met                         | V2    |
| `IdChangeWithIrq_A`              | IRQ ID changes only under correct conditions                            | V2    |

All testpoints verified via formal proof, not simulation.

## Advantages of FPV-Only Approach for PLIC

1. **Exhaustive coverage:** Formal proves correctness across entire state space
2. **Priority arbitration:** Difficult to achieve coverage of all priority combinations via simulation
3. **Symbolic variables:** Single assertion covers all interrupt sources and targets
4. **No corner case misses:** Formal finds corner cases simulation might miss
5. **Less maintenance:** No complex UVM environment, scoreboards, or coverage models
6. **Faster feedback:** Formal proof faster than extensive simulation regression
7. **Protocol compliance:** TileLink checker provides protocol-level verification

## Limitations and Considerations

1. **No dynamic timing:** Formal doesn't verify timing-related issues (covered by synthesis/STA)
2. **Limited scalability:** Formal struggles with very large designs (PLIC is small enough)
3. **No integration testing:** Chip-level integration tested separately at chip DV level
4. **Tool dependency:** Requires JasperGold or VC Formal license
5. **V3 incomplete:** Final verification stage not yet completed

## Related Interrupt Testing

While RV_PLIC verified via FPV only, **interrupt integration** tested elsewhere:

1. **Chip-level DV** (`hw/top_earlgrey/dv/`) - Tests interrupt flow end-to-end with CPU
2. **IP-level DV** - Each IP's DV testbench verifies its interrupt outputs
3. **Software tests** - Firmware tests exercise interrupt handling via `opentitanlib`
4. **PLIC DIF unittest** - `sw/device/lib/dif/dif_rv_plic_unittest.cc` tests software interface

## Summary

RV_PLIC uses a **formal-only verification strategy** that:
- ✅ Proves correctness of interrupt routing, priority arbitration, and claim/complete protocol
- ✅ Uses symbolic variables for scalable verification across many sources/targets
- ✅ Includes TileLink protocol checking and bus integrity verification
- ✅ Achieves V2 verification stage with all key properties proven
- ⏸️ V3 final signoff pending (likely low priority given design maturity)

This approach is appropriate given PLIC's relatively simple, protocol-driven nature and avoids the complexity of a full simulation testbench for limited added value.
